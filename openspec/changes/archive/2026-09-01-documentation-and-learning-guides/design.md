## Context

O AppStart será usado por públicos diferentes: alunos, docentes, mantenedores e infraestrutura. A documentação precisa separar responsabilidades e permitir que o projeto seja entendido e evoluído sem conhecimento tácito.

## Goals / Non-Goals

**Goals:**
- Explicar instalação e primeiro uso.
- Explicar arquitetura e fluxo de requisição.
- Documentar criação de novas features.
- Documentar estratégia de testes e ADRs.
- Diferenciar práticas de desenvolvimento e produção.

**Non-Goals:**
- Substituir documentação específica de aplicações derivadas.
- Cobrir todo material didático externo do curso.

## Decisions

- Tratar README como porta de entrada do projeto.
- Separar guias por público e por tema.
- Usar ADRs para decisões arquiteturais relevantes.
- Incluir orientação operacional para docentes e mantenedores.

## Risks / Trade-offs

- **Documentação desatualizada** → Vincular docs a fluxos reais e revisar junto com mudanças.
- **Excesso de conteúdo introdutório no README** → Manter README curto e aprofundar em guias dedicados.
- **Confusão entre dev e produção** → Criar seções e exemplos distintos.
